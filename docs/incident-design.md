# 事件闭环的设计取舍

## 为什么采用显式业务状态机

SOP 事件登记中的追問、审批和写工单属于业务规则。LLM 在真实入口中拆解子问题、评估证据并选择搜索、追问、冲突或停止；最终起草的方案仍需人工审批。`IncidentService` 注入 `Planner` 协议，具有 `investigate` 能力的适配器进入 `ResearchAgent`；基础演示适配器保留单次检索/生成。真实适配器复用混合检索与 LLMService，演示适配器返回固定样例。

正在进行的模型调用不做中间检查点：进程在规划完成前退出时，需要重新提交；已保存的追问、待审批和终态可以恢复。

这不是通用自主 Agent，也不宣称使用了 LangGraph interrupt：新闭环使用应用层持久化状态机；原有 LangGraph 仍负责 RAG。这个选择把可恢复边界放在提交给人的完整方案上，代码较少且能独立测试。

## 审批的具体语义

`awaiting_approval` 中包含事实、方案、来源原文和 version。审批请求只传 expected_version 与 approve，不能提交任意执行参数。修改事实重新检索规划，成功保存后版本增加；旧审批返回 409。

规划在数据库事务之外执行。保存采用 compare-and-swap；如果规划期间发生审批，新方案无法覆盖已完成状态。修改与审批并发时先提交者生效，另一请求失败并要求刷新。

`IncidentStore.decide` 开启 `BEGIN IMMEDIATE`，读取归属与状态，在一个事务中记录决定、模拟工单及最终快照。`mock_tickets.incident_id` 唯一。重复相同版本与相同决定返回现有结果；相反决定不允许翻转。事务提交前崩溃则全部回滚，提交后响应丢失可重试。

这个原子性只适用于同一 SQLite 文件中的模拟工单。接入真实外部工单时需要 outbox、稳定幂等键、投递重试与结果对账，不能沿用“本地事务实现 exactly once”的假设。

## 证据检查能证明什么

模型输出必须通过 Pydantic schema，且每个步骤的引用 ID 存在、quote 是对应来源的连续原文。缺资料、空步骤或模型明确报告不足时不得进入审批。

原文包含不等于语义支持，也不等于文档仍有效。页面同时展示指令和引文，让操作人核查。对真实领域应继续增加 SOP 版本有效期、设备适用性标注与独立答案支持评测。

## 权限与恢复

真实入口从验证后的会话取得 user_id，按用户读取和更新事件；不存在与无权限都返回 404。现阶段提交人也可审批自己的方案，代表 human-in-the-loop，不代表双人复核制度。共享知识库继承原工程模型，不宣称企业多租户隔离。

演示入口固定 local-demo 身份，禁止将其当作公开多人服务。SQLite 默认路径分别为 data/demo-incidents.sqlite3 与 data/incidents.sqlite3，可通过 SOP_DEMO_DB / SOP_INCIDENT_DB 指定，保留该文件即可跨重启恢复。前端只在 localStorage 保留最后事件 ID，数据库是事实来源。

## 面试时可复现的追问

- 并发审批是否重复？运行 `test_concurrent_approval_is_idempotent`。
- 分析还没完成时，另一个请求审批了旧方案？运行 `test_concurrent_revision_cannot_overwrite_approval`。
- 模型伪造来源、引用或报错？运行 `test_invalid_model_results_fail_closed`。
- 为什么没有给 Agent 自主写工单权限？审批记录需要绑定用户看到的精确版本。
- 为什么不直接声称混合检索更好？需在同一语料、相同 k、标注查询上做对照，并报告负例表现。

简历可描述已实现的内容：**基于 FastAPI 与混合检索构建 SOP 事件助手，将结构化方案生成与版本化人工审批分离，通过异步事务、唯一约束和乐观并发控制实现模拟工单幂等创建，并建立异常与并发回归测试。** 不填未经测量的效果提升数字。


## 自适应调查与验证

`ResearchAgent` 的状态保存在单次调用的 `ResearchResult`，包含子问题、累计证据、查询轨迹、冲突引文、逐步骤支持报告和预算计数。模型选择动作，控制器检查合法性。结构完整且全部子问题关联真实证据后才允许生成；原文存在和模型语义支持检查均通过才返回 ready。

检索结果用文件名、页码和内容的 SHA-256 派生稳定 ID，在多轮中去重。上下文有片段数、单片段字符数和总字符数限制；传入模型与返回审批记录的都是同一受限片段。不同内容版本保留不同 ID，不基于日期自动覆盖旧文档。

超时和上游失败返回部分证据与轨迹，不输出可审批方案。调用数是模型服务调用数，内部重试另计。语义评审是另一轮模型调用，并非形式证明；真实效果需要通过领域难例测量。
